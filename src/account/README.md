# 公共账号传输层

`BackendAccountClient` 通过现有可取消的 `HttpTransport` 调用固定生产 HTTPS 服务，提供登录渠道、登录/绑定挑战、凭据交换、刷新、资料、昵称修改、退出和注销账号。`authorization_url` 仅作为响应数据返回，本层不会启动浏览器。

所有方法是同步的，应从后台工作线程调用；不得阻塞 GTK 或 IBus 主循环。调用方传入取消检查，发请求前与处理响应前都会检查。普通 JSON 上限为 1 MiB，请求体最多 64 KiB；凭据限定为服务端的 64 位小写十六进制格式，响应中的令牌类型、有效期和用户标识也会校验。错误只保留 HTTP 状态与取消标识，不传递上游原始正文。

该类不保存令牌，不创建后台刷新线程，也不自动重试登录、刷新或写操作。账号页通过下述会话协调器使用该类；IBus 授权消费及其他登录渠道仍需继续接入，不能把本模块测试通过当作完整登录流程已交付。

CMake 的 `backend_account_client` 测试覆盖字段和方法映射、身份绑定、令牌校验、取消、大小限制、错误正文隔离及不发送非法请求。生产协议验收已使用临时账号验证资料、PATCH 昵称、刷新、退出、DELETE 注销和旧凭据失效；完整 Linux GTK/IBus 产品验收仍待后续完成。

## 会话凭据保存

`AccountCredentialStore` 使用 `SecretStore` 的独立 `AccountSession / msime` 条目保存一份带版本的 JSON，包含访问令牌、刷新令牌、用户信息和绝对到期时间。整个会话一次替换，避免两次读取混入不同账号的令牌。生产实现使用 libsecret，不提供明文文件回退；须从后台线程串行调用。

不存在的条目返回空值；Secret Service 不可用、格式损坏、未知版本、非法令牌或到期字段均抛出固定错误，不自动删除记录或透传底层诊断。已过期的访问令牌仍可读取，以便会话协调器使用刷新令牌恢复；保存失败不得向应用发布新会话。清除是显式且幂等的操作，失败会被报告。

`account_credential_store` 验证重新读取、过期凭据保留、账号完整替换、存储不可用、损坏记录、写前校验和清除。真实 Secret Service 集成测试另行验证账号用途与已有 API 凭据隔离。该适配层由 GTK 账号页的会话协调器调用。

## 会话生命周期

`AccountSession` 在后台工作线程中串行执行恢复、登录、刷新、退出和注销。启动先调用 `restore()`，保存成功后才发布登录结果；访问令牌剩余不超过 60 秒时刷新，并先保存结果。并发访问共用同一次刷新，刷新结果必须仍属于原用户。

每次账号变更都会递增 `SessionSnapshot.generation`。发起登录、获取授权、退出或注销时传入界面捕获的代次，陈旧操作会在请求前失败。应用把后台结果送回 GTK 时也须比较代次，丢弃迟到结果；快照仅含用户信息，不含令牌。网络操作期间持有会话锁，因此包括 `snapshot()` 在内的方法不能从 GTK 主循环直接调用。

临时刷新或退出失败保留会话；刷新返回 401 时清除会话。退出或注销已在服务器完成时，即使本地密钥环删除失败也停止使用旧会话，同时报告清理错误。这里不启动后台定时任务；由账号页面操作或 API 授权访问触发刷新。

`account_session` 覆盖存储失败、陈旧代次、八路并发刷新、刷新账号校验、取消和服务器失效。生产临时账号另已验证恢复 → 刷新并保存 → 退出 → 注销以及旧凭据失效；验收使用内存存储适配器与真实 HTTPS，不能替代 Linux 桌面 Secret Service 的完整产品验收。

## GTK 账号页

设置侧栏的「账号」页面使用服务端能力开关展示手机、邮箱验证码登录。验证码挑战绑定发起时的登录账号，用户可显式更换；登录成功后清除输入框并读取在线资料，展示已绑定登录方式，提供昵称修改、资料刷新、退出和二次确认的账号注销。网络与密钥环通过 GTask 在后台处理，页面切换保留同一页面和会话实例；销毁窗口会取消请求，完成回调不会再访问已销毁的控件。

当前尚无 Apple、Google、微信的 Linux 浏览器授权回调流程。生产手机、邮箱渠道也尚未开放，界面会说明当前无法使用这些渠道；不能将模拟验证码测试当作生产手机/邮箱验收。

`account_panel` 在 Xvfb 下驱动真实 GTK 控件，验证模拟验证码登录、凭据保存、退出、页面重新挂载，以及请求中关闭控件。Ubuntu 24.04 arm64 容器已通过 CMake 构建实际设置程序及账号测试目标。账号生命周期、凭据保存、协议、设置检查、GTK 流程、真实密钥环 GTK 流程和密钥用途隔离共 7 项 CTest 通过；其他架构、打包与 IBus 产品检查仍由 CI 验证。

资料读取与昵称修改共用账号代次和自动刷新授权。资料响应必须匹配当前用户，再写入 Secret Service；读取返回 401 时清除会话。昵称提交后重新读取服务端资料，保存失败保留界面输入供重试。GTK 测试已覆盖昵称提交、资料刷新及保存后的凭据缓存，线上临时账号也验证了会话层的资料读取和昵称保存。

账号已登录时，同一验证码表单用于「绑定登录方式」。发起挑战和提交验证码都通过当前账号授权，挑战记录绑定发起时的账号代次；切换账号或会话失效后不能继续旧挑战。服务端返回用户必须与当前账号一致，保存成功后更新会话代次并刷新绑定列表。

会话测试覆盖绑定用途与授权头、返回其他账号时拒绝、保存失败保留原状态、成功后拒绝旧代次。GTK 测试覆盖邮箱登录后绑定手机、刷新绑定列表且保持用户 ID。该流程使用模拟验证码服务，生产手机／邮箱绑定仍须在渠道配置后验收。

`account_panel_secret_service` 在临时 HOME/XDG 目录和独立 D-Bus 会话内启动 gnome-keyring，再驱动相同的 GTK 登录、绑定、资料、昵称和退出流程。它使用真实 libsecret 保存完整会话，HTTP 验证码响应仍为合成测试数据，不读取开发者的桌面密钥环。

## 云剪贴板协议

`BackendAccountClient` 提供列表/搜索、显式开关、上传、单条删除和清空。关闭开关会由服务端清空已有记录。列表最多 50 条，响应限额 2 MiB，以容纳每条最多 4000 个 UTF-16 单位的合法 JSON 转义文本；请求校验 UTF-8、NUL 和长度，搜索逐字节编码，删除 ID 限定为 64 位十六进制。

账号页已通过会话协调器接入手动云剪贴板：先加载服务端开关和列表，再显式开启、输入或粘贴文字上传、搜索、复制选中记录、单条删除或清空。不会自动读取或上传系统剪贴板。关闭或清空需二次确认，取消不发出写请求；退出或账号代次变化会清除列表和未上传草稿。生产临时账号已验证开启、上传、特殊字符搜索、单条删除、清空、关闭清理，以及关闭后上传返回 403；验收账号与数据已删除。

云剪贴板读写通过 `AccountSession` 串行授权，旧账号代次在网络请求前拒绝，401 会清除会话。GTK 测试在内存与真实 Secret Service 两种模式下覆盖开关、手动上传、搜索、复制、删除、取消清空和退出缓存清理。真实密钥环模式另在 ASan/UBSan 且 `detect_leaks=1` 下通过；只按 `gtk-lsan.supp` 处理已定位的桌面库分配，不关闭应用代码泄漏检查。
